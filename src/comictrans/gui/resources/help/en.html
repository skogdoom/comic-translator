Reviewing a plan

This window edits one plan file. It does not translate anything and it does not change your pages — the only file it ever writes is the plan, and only when you save it.

How the work goes

Extract read your pages, found the lettering, and wrote a plan: one entry per region, with an outline, the colours read off the page, and the text it recognised. Nothing has been drawn yet.

You work through the plan here. Fix an outline extract got wrong, write the translation, and mark what should be left alone.

Render draws the plan onto copies of your pages, into a directory you choose. Every decision it makes comes from the plan, which is what lets you change one translation, run it again, and have only that text change.

The outline colours

Every region on the page carries an outline, and its colour says where that outline came from.

     Green — traced from a balloon extract found. The outline follows a real edge on the page.
     Orange — no balloon was found, so this is a padded box around the text extract read. It is a guess, and it is the one to check first.
     Violet — drawn or reshaped by hand, here. Neither traced nor guessed: somebody decided this shape.
     Blue — selected. Whichever of the three it would otherwise be.
     Dashed red — flagged: something about this region is worth a second look. What, exactly, is in the region panel; the list is below.

Green and orange are the same two colours extract --debug-dir draws, so an overlay written during detection and this window agree about which regions were traced.

The flags

A flag is a reason to look, not an error. A page can be finished with flags still on it, and rendering never refuses one because of a flag.

approximate geometry
No clean balloon outline was found and the region is a padded box around the text. It may cover artwork it should not, or miss lettering it should. Reshape it, or draw a new one.

low confidence
The recogniser was unsure of what it read. The source text may be wrong, which matters because it is what you are translating from.

held back (no translation)
The translation is empty and the region is not skipped. Rendering leaves this region completely alone — not erased, not half-drawn — and names it in the report.

same as source
The translation is still the text extract seeded it with. Not an error: a name or an exclamation can be a correct translation of itself. Worth knowing before you call a page done.

overlaps another region
Two outlines share enough area that one will draw over the other. Either reshape one, or merge them if they are two tracings of the same balloon.

skipped
You have said to leave this region alone. It is shown separately from the others because it is a decision rather than a defect.

The page list counts flagged regions per page, and Next Flagged Region walks them in order, so a chapter can be worked through without opening every page to look.

What the preview tells you

Render Preview swaps the page for the same page rendered. It calls the same code the render pass calls, on the plan as it stands in this window — including edits you have not saved — so what you see is what you would get.

It answers: does the translation fit the balloon, does the erase strategy actually remove the old lettering, are the fill and text colours right against this artwork, and does the font resolve. The status line says how many regions had a problem and names them.

It does not: write anything to disk, look at any page but this one, or tell you whether the translation is any good. It also costs a real render, which is why it is a key you press rather than something that happens as you type.

Press it again to go back to the outlines. The zoom and the scroll position are held across the swap, so a balloon you were looking at closely is still there when you come back.

Getting around

The Pages panel lists the plan's pages with a region count and a flag count each. Drag a row to put the pages in the order you read them.

Next Region and Previous Region step through the regions in reading order, and walk onto the next page at the end of this one. Next Flagged Region skips to the next one worth a look.

The page starts fitted to the window. Zoom in and out, fit again, or go to actual size from the View menu; the zoom is remembered per page, because a dense page of captions and the splash opposite it want different ones.

The line under the page says what a click does right now — it changes when you enter a mode, and it names the modifier the way your keyboard does.

This window speaks your system's language where it has been translated into it, and English otherwise. This guide follows the same language, with English behind it, so help is here either way. The plan file itself is never translated: its languages are the comic's.

Saving, reverting and running

Save writes the plan back where it came from. The title bar's modified marker tracks what is on disk, so undoing back to your last save clears it. Revert to Saved re-reads the file and throws away what is unsaved.

Extract Pages runs detection and recognition over a folder of pages and writes a new plan. Render Pages draws the open plan into a directory you choose. Both run in the background: the window stays usable, and a panel along the bottom reports what happened.

Rendering will not write inside the folder your pages are in, and there is no way to make it. That is the one refusal in this tool with no override, and it is what keeps your scans as they were.
